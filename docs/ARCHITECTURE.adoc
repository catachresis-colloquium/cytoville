= Cytoville architecture
// SPDX-License-Identifier: CC-BY-SA-4.0

The Rust runtime owns game rules, deterministic random state, native rival memory
and Enaction causal traces. Bevy renders that runtime locally or receives validated
runtime snapshots from the Elixir service. Both paths use the same rules.

== Execution paths

* UMS generates and validates the city/cell profile, then compiles a content package.
  The Rust worker validates that package before accepting a session.
* Elixir authenticates invitations and resume keys, serializes commands per session,
  and sends the authenticated seat and expected revision to its Rust Port worker.
* Rust rejects illegal or stale commands atomically. Accepted commands enter the
  Enaction trace; in native-rival mode the Zig Evil Weevil kernel selects intents
  through the Idris2-defined ABI, and Rust applies legal actions.
* The complete runtime returns through Elixir to Bevy. Initial connections, polling
  and reconnects all validate the game, content and causal trace.
* Elixir checkpoints acknowledged transitions, credentials and runtime to a private
  directory. Resume lazily restores a lost session through Rust's validated load.

== Invariants and evidence

Seats belong to server-issued credentials. Revision checks prevent replay.
A failed command cannot partially change the Rust runtime. UMS content is fixed
for a connected session. Native memory and trace survive checkpoint recovery.

`scripts/cytoville-check.sh` runs ABI checks, rule tests, real Elixir TCP tests and
`scripts/cytoville-e2e.sh`. The latter edits and compiles a UMS package, starts an
Elixir host, then connects using the same transport used by the Bevy application.
It checks two-human play, reconnect and server-hosted Evil Weevil execution.
It does not certify graphical interaction or an internet deployment.

Dependencies are pinned in Cargo.lock, Cargo.toml and the Evil Weevil gitlink.
See link:architecture/MULTIPLAYER.adoc[Multiplayer] for operation and limits.
