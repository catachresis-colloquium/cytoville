= Contributing to Cytoville
:revdate: 2026-11-07

== Ways to help

You do not need specialist hardware to contribute. Useful work includes
reproducible bug reports, accessibility and keyboard testing, translations,
biological accuracy, art, audio, scenario balance and small reference kernels.
Use https://github.com/catachresis-colloquium/cytoville/issues[project issues]
to discuss a focused change before a large implementation.

For future computing, read
link:architecture/FUTURE-COMPUTING.adoc[the research and implementation boundaries].
The disabled settings are an invitation to help build support. They are not a
claim that the backends already exist or that buying a device will enable them.
Ask vendors and research funders for documented interfaces, open drivers,
accessible research hardware and reproducible performance and energy evidence.
Speak in your own name; this project does not send advocacy messages for you.

AI can help explain papers, draft experiments, generate test cases and review
code. Check original sources, run the experiment and report failures as well
as successes. Include tool/model versions and how generated work was validated.
A generated proof or performance claim is not evidence until independently checked.

== A useful performance report

Include the game version, operating system, renderer/backend, display resolution
and scale, CPU/GPU, and a short reproduction. Separate startup, button response,
frame pacing, game simulation and shutdown. Compare release builds on the same
machine with the same workload. The opt-in `--profile FILE` records application
CPU/update timings; it does not measure click-to-photon latency or prove GPU
throughput. Remove usernames, paths, keys, resume tickets and private player data
before sharing logs. Do not upload saves or diagnostic bundles without reviewing them.

== Build and verify

The supported development path and exact dependencies are in
link:../README.adoc[README], link:../mise.toml[mise.toml] and the CI scripts.
The current native path uses Rust, Bevy, Zig 0.16.0, Idris2 0.8.0,
Elixir 1.19 and Erlang OTP 28. Linux/WSL also needs the graphics/audio development
libraries listed in the README. Initialise the pinned submodule:

[source,bash]
----
git clone --recurse-submodules https://github.com/catachresis-colloquium/cytoville
cd cytoville
just build
just run
just test
just quality
just validate-rsr
just assail
----

Normal play uses a release build. Proof tooling has separate installation
requirements: `just verify-budget` covers the selected resource primitives,
not the whole game. See link:verification/PROOF-STATUS.adoc[proof scope].
A missing analysis tool is an unperformed check, not a clean scan.

== Code and review

Read the repository deed and link:status/ROADMAP.adoc[roadmap]. Keep Rust game
rules authoritative, Idris2 ABI declarations and Zig FFI aligned, and preserve
the biological ontology used by UMS. Shared accelerator operations belong in
Enaction; a Cytoville integration needs a real workload and verified contract.
Do not add a device-name switch that claims support without an implementation.

Keep changes focused, use signed commits and SPDX headers, preserve existing
licences, and open a pull request. Games use AGPL-3.0-or-later and prose uses
CC-BY-SA-4.0 under metadatastician's licence policy; inherited tooling retains
its own licence. Follow the repository's protected checks and review policy;
never bypass it to obtain a green merge. Enable auto-merge for ready PRs
when available, retaining all required checks and reviews. Document the actual
checks run and remaining limitations. Research and experimental code must retain those labels.

New dependencies need a concrete purpose, provenance review and locked versions.
Update the appropriate architecture document for a new runtime boundary.
Report estate-wide standards questions to
https://github.com/metadatastician/standards[metadatastician/standards].
